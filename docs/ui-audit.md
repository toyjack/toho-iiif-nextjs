## 2. 整体评价

信息架构简单清晰，URL 保存筛选状态、检索框的 IME 处理和 combobox ARIA 写得比较用心，纸色／墨色的基调也与内容相称，页面在 375px 与 1280px 下都没有横向溢出。

但目前的成品感被几个基础问题明显拉低：

1. **主题里的一处尺寸设置把所有按钮、输入框、徽章压成了一半高度**，这是当前最显眼的视觉缺陷，也是可访问性问题。
2. **品牌金色被当作文字色使用，对比度只有 2.65:1**，导航当前项、链接、标题都受影响。
3. **书目列表一次渲染 335 张卡片**，页面高 3 万像素以上，移动端超过 8 万像素。
4. **语言与用语不统一**：同一含义在首页用日文，在书目页用中文。
5. 首页像通用模板的落地页（装饰图标、宣传文案），而没有把检索和书目本身放在首位。

## 3. 具体问题

编号用于后文引用。每条给出位置与证据。

### A. 设计系统与主题

**A1. 控件尺寸被主题减半（P0）**

- 位置：`src/app/globals.css:54-55`，`--size-selector: 0.125rem; --size-field: 0.125rem;`（DaisyUI 5 默认均为 `0.25rem`，控件高度是它的倍数）
- 实测（1280×800）：

  | 元素 | 高度 | 字号 |
  | --- | --- | --- |
  | `btn`（Logo、移动端菜单按钮） | 20px | 20px / 14px |
  | `btn-lg`（首页「漢籍一覧」） | 24px | 18px |
  | `btn-sm`（閱覽、クリア、排序方向） | 16px | 12px |
  | `input-sm` 检索框、`select-sm` | 16px | 12px |
  | `checkbox-sm` | 10×10px | — |
  | `badge-sm` | 10px | 12px |
  | `badge-xs` | 8px | 10px |

- 后果：
  - 徽章的底色条比文字还矮，文字溢出色块上下（截图中「閲覧可能」「松本文庫」等均如此）。
  - 按钮、下拉框像一条细线，`btn-lg` 的主行动按钮没有分量。
  - 多数可点击目标低于 WCAG 2.2 的 2.5.8 Target Size (Minimum) 24×24px：`btn-sm` 16px、复选框 10px、移动端菜单按钮 54×20px。

**A2. 主色作为文字色对比度不足（P0）**

实测对比度（前景 / 背景）：

| 组合 | 对比度 | 使用位置 | AA（正文 4.5 / 大字与图形 3） |
| --- | --- | --- | --- |
| `primary` / `base-100` | 2.65 | Logo、导航当前项、`link-primary`、统计数字、404、分类图标 | 不通过（大字也不通过） |
| `primary` / `base-200` | 2.42 | 页脚链接 | 不通过 |
| `info` / `base-100` | 3.36 | 「全国漢籍DB」（`btn-ghost btn-info`，12px） | 不通过 |
| `success-content` / `success` | 2.94 | 「閲覧可能」徽章 | 不通过 |
| `secondary-content` / `secondary` | 3.99 | 朝代徽章（12px） | 不通过 |
| `secondary` / `base-100` | 4.19 | 统计数字（大字） | 大字通过 |
| `accent` / `base-100` | 4.34 | 统计数字（大字） | 大字通过 |
| `base-content/50` / `base-100` | 3.49 | 检索说明文字（12px）、候补分组标题 | 不通过 |
| `base-content/60` / `base-100` | 4.79 | 出版信息（12px） | 通过（余量很小） |
| `base-content/70` / `base-100` | 6.74 | 说明文字 | 通过 |
| `primary-content` / `primary` | 6.78 | 主按钮 | 通过 |
| `error` / `base-100` | 5.01 | 「クリア」 | 通过 |

另外，未公开的书卡整体 `opacity-75`（`books.tsx:337`），会把上述数值再压低（未逐项测量）。

- 位置：`globals.css:18-47` 的色值；使用点见 `header.tsx:23,34`、`page.tsx:33,41,68`、`footer.tsx:15`、`books.tsx:352,364,416`。

**A3. 没有字体方案（P1）**

- 证据：`layout.tsx` 未引入字体，`globals.css` 无 `font-family`；实测为系统默认无衬线。
- 影响：站点内容是汉籍旧字形与扩展区汉字（构建警告里出现 `𤊹`、`𧻰`），在 `lang="ja"` 下显示效果完全取决于访问者系统字体，缺字时会回退成不同风格的字形。「典籍」气质也只靠颜色表达。
- 「仅代码」：缺字回退的实际外观没有在不同系统上验证。

**A4. 语义色用途不稳定（P2）**

- 分类用 `badge-primary`，朝代用 `badge-secondary`，版本用 `badge-outline`，匹配方式用 `badge-ghost`，可阅读用 `badge-success`，残本用 `badge-warning`——一张卡片上最多同时出现 6 种徽章样式（`books.tsx:351-410`），颜色没有传达主次。
- 首页三张统计卡分别用 primary／secondary／accent 上色（`page.tsx:68,91,120`），颜色只是装饰。
- 「クリア」始终是 `text-error` 红色（`books.tsx:159`），即使没有任何筛选条件。

### B. 功能性缺陷（影响流程）

**B1. 首页「漢籍一覧へ」链接到错误页（P0）**

- 位置：`src/app/page.tsx:332`，`href="/viewer"`。
- 实测：`/viewer` 显示红色警告卡「漢籍のIDが見つかりません」。应为 `/books`。

**B2. `/books` 出现 hydration 错误（P1）**

- 实测：开发模式下访问 `/books` 两次，控制台均报 `Hydration failed because the server rendered text didn't match the client`，出错位置在 `BooksComp` 的卡片网格内，React 会放弃服务端结果、在客户端整树重渲染。
- 原因未确定。已排除卡片顺序：服务端 HTML 与客户端的 335 个标题顺序完全一致。需在修复阶段定位（生产构建下是否出现也未验证）。

**B3. 阅读器「戻る」的逻辑（P1，仅代码）**

- 位置：`components/back-button.tsx:10-16`。该按钮只在 `/viewer` 使用，`pathname !== "/books"` 恒为真，所以总是 `router.back()`。
- 影响：从外部链接或书签直接进入阅读器时，「戻る」会离开本站或无反应；`else` 分支是死代码。

### C. 信息架构与内容

**C1. 书目列表不分页（P1）**

- 实测：`/books` 一次渲染 335 张卡片（DOM 中 `.card` 336 个）。页面高度桌面 31,219px、移动端 82,692px。
- 没有分页、分组标题、「回到顶部」或分类锚点；排序默认按书名，同一分类的书并不相邻。
- 移动端筛选面板高 439px，第一张书卡出现在距顶 755px 处，首屏（812px）几乎看不到结果；筛选面板不可折叠（`lg:sticky` 只在桌面生效）。

**C2. 语言与用语不统一（P1）**

界面语言声明为 `lang="ja"`，但同一概念有两套写法（实测页面文本 + 代码）：

| 含义 | 首页 `page.tsx` | 书目页 `books.tsx` |
| --- | --- | --- |
| 著者 | `著者：`（298） | `作者：`（381） |
| 阅读 | `閲覧`（323） | `閱覽`（429） |
| 有印 / 有注 | `印有` / `注有`（313, 316） | `有印` / `有註`（400, 405） |
| 卷数 | — | `卷數：`（387） |
| 筛选项 | — | `全部分類`、`全部朝代`、`全部類型`、`版本類型` |
| 版本未知 | 不显示 | 徽章显示 `未知` |

站名也有三种：页面与 `metadata` 用「東方学IIIF図書館」，`data/site.yaml` 为「東方學デジタル圖書館」，`AGENTS.md` 称「東方學デジタル圖書館 Ver.IIIF」。移动端 Logo 缩写为「東IIIF」（`header.tsx:36`），不易理解。

统计用语：首页「総蔵書 335 点漢籍」，`/about`「収録漢籍 335 部」，`/books`「335 部漢籍が公開されています」——而实际只有部分可阅读，「公開されています」容易误解。

**C3. 首页偏模板化，重点不在书目（P1）**

- 没有检索入口；检索只在 `/books` 侧栏里。
- 分类图标与内容无关且重复：两组分类共用同一个 5 图标数组（`page.tsx:165-171` 与 `220-226` 完全重复），其中第 3 个是烧瓶、第 4 个是垃圾桶，分别落在「子部／松本文庫」「集部／内藤文庫」上（截图可见）。
- 「おすすめの漢籍」的副标题是「ランダムな6部の漢籍をご紹介します」，名实不符。
- 「プラットフォームの特色」三栏是通用宣传文案，「高画質閲覧」配的是心形图标（`page.tsx:400`）。
- 文库分类里「村本文庫 1 部」「中江文庫 2 部」与「松本文庫 89 部」同等大小展示。
- 首屏之后连续四个居中标题 + 副标题 + 卡片网格的同构区块，缺少主次。

**C4. 阅读器页的外壳挤占空间且信息错位（P1）**

- 实测：站点导航 + 「漢籍ビューア」栏 + ID／manifest 栏三层叠加，Tify 起始于距顶 175px（桌面）／173px（移动）。
- 实测：Tify 高 720px，而外层容器 `h-[calc(100vh-120px)]` 只有 680px（`viewer/page.tsx:133` 与 `tify.tsx:25` 的 `height: 640px; minHeight: 90vh` 互相冲突），页面总高 1126px，需要滚动整页才能看到阅读器底部，下面还接着页脚。
- 页面有两个 `<h1>`：「漢籍ビューア」和 Tify 内的书名。
- 页面外壳不显示书名、著者、版本、分类；最显眼的反而是 manifest 的相对路径（纯文本链接，无「IIIF manifest」说明、无复制功能）。
- `document.title` 仍是站名（实测），多开标签页时无法区分书。

**C5. 页面标题缺失（P2）**

- 实测 `/books`、`/viewer` 的 `<title>` 都是「東方学IIIF図書館」；`/sitepolicy` 未设置 `metadata`（仅代码）。只有 `/about` 有独立标题。

### D. 交互状态

**D1. 卡片的悬停反馈与可点击区域不一致（P1）**

- 首页推荐卡与书目卡在整卡悬停时有阴影、边框和标题变色（`page.tsx:279-282`、`books.tsx:334-346`），但可点击的只有右下角 16px 高的按钮；整卡不是链接。
- 分类卡是整卡链接，行为不同。

**D2. 「準備中」是可聚焦的假禁用按钮（P1）**

- 位置：`books.tsx:432`，`<button className="btn btn-disabled">`。
- 实测：`disabled` 属性为 `false`、`tabIndex` 为 0，键盘用户会在每张未公开书卡上多停一次，且读屏不会报「不可用」。

**D3. 加载与错误状态缺失（P1）**

- `/books` 的 `<Suspense>` 没有 `fallback`（`books/page.tsx:8`）。
- 阅读器加载前显示裸文本「IIIF Viewer」（`tify.tsx:26`）；实测加载后约 4 秒内只有灰色画布，没有进度提示。
- manifest 或图像服务失败时没有站点层面的提示；没有 `error.tsx`（仅代码）。

**D4. 空结果状态过于简略（P2）**

- 实测 `/books?q=zzzzqqq`：只有一行灰字「条件に一致する漢籍はありません。」，没有「清除条件」按钮或改写建议；筛选条件也不以标签形式显示在结果区。

**D5. 候补列表在窄侧栏中被挤压（P2）**

- 实测 `q=zhouyi`：候补行里书名被截成「周易筮述…」，剩余宽度被 ID、「拼音で一致」「閲覧可能」占用（侧栏 270px）。

### E. 可访问性

**E1. 表单控件没有可编程关联的标签（P0）**

- 位置：`books.tsx:167-253`、`267-277`。`<label>` 既没有 `htmlFor` 也没有包住控件。
- 实测：检索框、三个筛选下拉框、排序下拉框共 5 个控件，`labels` 为空且无 `aria-label`（5/5）。只有「現在閲覧可能」复选框被 label 包裹。
- 违反 WCAG 1.3.1、4.1.2；点击标签文字也不能聚焦控件。

**E2. 缺少地标与跳转链接（P1）**

- 实测首页地标只有 `FOOTER` 和页脚里的 `NAV`。顶部导航是 `<div class="navbar">`，没有 `<header>`／`<nav>`；除阅读器外没有 `<main>`；没有「本文へスキップ」链接。

**E3. 装饰性图标未隐藏、外链无提示（P2）**

- 实测首页 21 个 `<svg>` 全部没有 `aria-hidden`。
- 3 个 `target="_blank"` 链接没有新窗口提示。
- 页脚与利用规约里的「CC」图标并不是 Creative Commons 标志（通用路径，`footer.tsx:30`、`sitepolicy/page.tsx:20`）。

**E4. 焦点样式（未验证）**

- DaisyUI 的 `btn`、`input`、`select` 自带 `:focus-visible` 轮廓；但 `<a class="card">`（分类卡）与页脚、`/about` 的徽章链接没有组件级焦点样式，依赖浏览器默认。需要用真实键盘确认。

### F. 响应式

- 375px 下无横向溢出（实测 `scrollWidth` = 375）。
- 首页 H1 为 48px，在 375px 下折成两行，末行只剩一个「館」字（截图）。`text-5xl` 没有响应式降级（`page.tsx:33`）。
- 移动端菜单按钮 54×20px（见 A1）；菜单项高 31px。
- `/books` 筛选面板占满首屏（见 C1）。
- 阅读器在移动端可用区域只有约 640px 高，而 Tify 设为 731px（见 C4）。
- 导航在 `lg`（1024px）以下才折叠，而四个链接在 768px 应当放得下（仅代码，未截图）。

### G. 排版与间距

- `/sitepolicy` 没有 `max-w`（`/about` 有 `max-w-3xl`），桌面上正文行长撑满 `container`（仅代码）。
- 两个文档页正文用 `text-base-content/70`～`/80`，长文可读性不如直接用正文色。
- 页头留白不统一：`/books` 用 `py-8` + `text-4xl`；`/about`、`/sitepolicy` 用 `my-8` + `text-3xl`；首页区块 `py-16`。
- 页脚版权年份写死为 2025（`footer.tsx:20`）。
- 书名里的全角空格（如「周易正義　十四卷」）是原文，应保留；但卡片 `line-clamp-2` 会在长书名处截断，没有 `title` 提示全文。

### H. 代码结构（影响一致性的部分）

- `page.tsx` 437 行，分类区块整段复制两次；书卡在首页和书目页各写一份且已经出现用语分歧（C2）。
- 图标是内联 SVG 路径字符串，同一个「书本」路径出现 5 处以上。
- 首页分类链接未做 `encodeURIComponent`（`page.tsx:176,231`），`/about` 做了；目前能用，但不一致。
- 被注释掉的 UI 块留在 `viewer/page.tsx`（下拉菜单、检索／书签按钮）与 `footer.tsx`。

## 5. Quick Wins（低风险、高收益）

1. `globals.css` 两行尺寸变量（#1）——一处修改恢复全站控件比例，是性价比最高的一项；改后需要目视复查。
2. 首页 `/viewer` → `/books`（#3）——一处字符串。
3. 5 个控件的 label 关联（#4）。
4. 书目页用语改为日文（#7 的文字部分）。
5. 「準備中」改成 `<span>`（#10 的一部分）。
6. `/sitepolicy` 加 `max-w-3xl`、各页补 `metadata.title`（#19）。
7. 装饰 SVG 加 `aria-hidden="true"`（#18）。
8. 首页 H1 响应式字号（#20）。

## 6. 需要结构性调整的问题

| 问题 | 为什么不是小改 |
| --- | --- |
| 色彩体系（A2, A4） | 主色同时承担按钮底色与文字色，两者对亮度的要求相反；需要重新定义「主色 / 主色文字 / 语义色」各自的用途并全站替换 |
| 书目列表规模（C1） | 涉及分页或虚拟滚动、URL 参数、与浏览器端检索的配合，以及移动端筛选的布局重做 |
| 阅读器外壳（C4） | 要重新决定站点导航在阅读器页是否保留、Tify 高度如何由布局而不是固定值决定；需对照 Tify 的初始化与卸载逻辑并做实机翻页验证 |
| 首页定位（C3） | 是内容取舍问题：首页应是「检索与浏览入口」还是「介绍页」，决定后才好删改区块 |
| 组件抽取（H） | `BookCard`、`CategoryCard`、图标、区块标题抽出后，用语与样式才不会再次分叉；改动面覆盖首页与书目页 |
| 字体（A3） | 需要在加载体积、旧字形覆盖率和扩展区回退之间取舍，可能涉及自托管字体 |
